What This Flow Does

When a user signs up or logs in, the system collects their email and password through a secure connection. The password is immediately turned into a scrambled code (hash) so it is never stored in plain text. The system checks the database to make sure the account exists or creates a new one.

Once the user is verified, the system creates two special access tokens: a short-lived access token and a longer refresh token. These tokens act like digital ID cards that prove the user's identity. The tokens are sent back to the user's device and stored safely there.

Every time the user asks the system for data or tries to do something, their device sends the access token along with the request. The system quickly checks the token to make sure it is valid and has not expired. If the token is good, the request goes through. If the token is missing or invalid, the system politely refuses the request and asks the user to log in again.

This flow is the security gatekeeper for the entire platform. It makes sure that only real, logged-in users can see private information and perform actions. The short expiration time on access tokens also helps keep accounts safe even if a token is somehow copied by someone else.
